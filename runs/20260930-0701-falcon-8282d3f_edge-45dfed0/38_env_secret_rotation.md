## Executive Summary

Hygiene is better than average in places: service secrets live outside Git in a root-only 0700 store generated by `openssl rand`; the redaction ledger is thorough; bootstrap tokens are stored hashed and the first-boot token is shredded; edge CI runs its own scanner plus gitleaks; two rotations are genuinely evidenced (central vector-ingest with a 401 negative test; edge certificate auto-renewal with the old cert rejected 403). The dominant problem is concentration and reuse: one interactive account reads every credential class — host sudo, Proxmox/Cloudflare/DO/R2/GitHub/UniFi/Wi-Fi in `/home/user/.env`, the edge CA private key and update-signing seed, and the legacy Wazuh/MCT stores — while root-run scripts source these user-writable files (SECRET-P1-002/007, SECRET-P2-005). Two classes are shared across environments: sensor images bake the owner Wi-Fi PSK and the host sudo password as the device account password with no post-flash rotation evidence (SECRET-P1-001). Rotation coverage is partial: most central classes are explicitly untested, the MCT tracker is 100% PENDING, and the signing seed has no procedure (SECRET-P2-004). Next: separate/rotate device credentials, split the owner `.env`, encrypt/relocate delivery backups and remove them from the release surface, then exercise the untested rotations.

## Findings

### Finding ID: SECRET-P1-001 - Host and Wi-Fi credentials are baked into sensor images and shared across environments
- Severity: P1 · Confidence: High · Area: SECRET
- Evidence: `bake_lab_test_image.sh:109-118` prefers `.env pi_password` else falls back to `.env sudo`; bake evidence `EDGE-ONBOARD/…bake-lab-test-image-lab{4,5,6}.out` shows `account password source: .env sudo (host credential)`; `bake_lab_test_image.sh:52-54,226-238` embeds `psk=$WIFI_KEY` from `.env wifi_key`; delivery keeps lab5–lab8 images + `-credentials.txt`/`-ssh-key` (0600) and READMEs instruct a post-login password change; no change evidence found.
- What is happening: one secret protects host sudo and device login; the Wi-Fi PSK is embedded in every image and never rotated.
- Why it matters: a device, microSD or image copy leaks the network PSK and a crackable copy of a host-privilege credential.
- User / business impact: one lost device/image can compromise the host and LAN.
- Security / privacy / reliability impact: cross-environment credential reuse defeats blast-radius isolation.
- Recommended fix: unique random device password + per-device Wi-Fi credential (or IoT SSID); remove the `sudo` fallback; change device passwords after flash and record it; rotate the PSK (treat as disclosed to image holders).
- Suggested validation: bake test proves source is `generated random`/`pi_password`; image must not contain the host credential hash; post-flash `passwd` capture.
- Owner suggestion: Edge maintainer + owner · Effort estimate: M · Dependencies: Owner agreement to rotate Wi-Fi PSK · Status: open
### Finding ID: SECRET-P1-002 - `/home/user/.env` is a single cleartext multi-class credential store driving root tooling (LIVE-P2-005)
- Severity: P1 · Confidence: High · Area: SECRET
- Evidence: `/home/user/.env` — 0600 user, 26 keys: host `sudo`; `prox_key`; `cf_*` (Cloudflare API/R2/Zero-Trust); `do_*`/`s3_*`; `gh_api`; `unifi_admin`; `wifi_*`; ntfy; `capture.sh:64-71` and `80-offsite-backup.sh:21-24` export the whole file (`set -a`) inside root-run scripts; `95-cloudflared.sh:31` requires it.
- What is happening: every credential class shares one file, one account and one compromise boundary; root jobs consume it from a user-writable path.

- Security / privacy / reliability impact: root escalation (sudo) plus third-party takeover paths.
- Recommended fix: split into per-purpose root-owned files (or a manager); root scripts pass individual variables; document each key.
- Suggested validation: test that root scripts do not source the whole file; grep check for unexpected key dependencies.
